# Требования к tu4ka (чек-лист приёмки)

Свод действующих требований — то, что система обязана делать и чего в ней
нельзя ломать. Собран из [CLAUDE.md](../../CLAUDE.md), [README.md](../../README.md),
страниц вики и фактического кода (пакет `server/`, `server/aqi.py`,
`server/static/index.html`) на 2026-08-03.

Это источник для ручной приёмки: субагент `tester`
([.claude/agents/tester.md](../../.claude/agents/tester.md)) сверяется именно с
этим списком. У каждого требования стабильный ID — на него ссылается отчёт.

Колонка «как проверяется»: **auto** — закрыто pytest/самотестом, руками
проверять незачем; **manual** — только глазами/руками (UI, эксплуатация);
**both** — есть автотест, но при правках стоит посмотреть и вживую.

## Приём данных от датчика (P)

| ID | Требование | Как |
|----|------------|-----|
| P1 | `POST /api/v1/push` принимает штатный формат прошивки airRohr. Формат тела, путь и порт 80 — конфигурация датчика, менять их на сервере нельзя без перепрошивки конфига датчика | auto |
| P2 | Маппинг `sensordatavalues`: `SDS_P1`→pm10, `SDS_P2`→pm25, `BME280_temperature/humidity/pressure`, `BMP280_temperature/pressure`, плюс голые `temperature/humidity/pressure/signal` | auto |
| P3 | Давление приходит в Па: значение > 2000 делится на 100 и округляется до 2 знаков; ≤ 2000 сохраняется как есть (уже гПа) | auto |
| P4 | Мусор в теле не роняет запрос: нечисловые значения, `inf`/`nan` и не-объекты в списке пропускаются; при дубле `value_type` побеждает первое значение | auto |
| P5 | `sensor_id`: `esp8266id` → `esp32id` → заголовок `X-Sensor` → пустая строка | auto |
| P6 | Метку времени ставит сервер (`int(time.time())`), ответ — `{"ok": true, "ts": <ts>}` | auto |
| P7 | `measurements.raw` хранит исходный JSON целиком — страховка для будущих миграций, не выпиливать при рефакторинге | auto |
| P8 | Basic auth: при заданном `TU4KA_PUSH_PASS` неверные, битые и не-ASCII креды → 401 (не 500), сравнение constant-time; при незаданном пароле push принимается без авторизации, а на старте пишется предупреждение в лог | auto |
| P9 | Защита от мусора: тело > 64 КБ → 413, невалидный JSON → 400, `sensordatavalues` не список → 400 | auto |

## API (C, H, Z, D)

| ID | Требование | Как |
|----|------------|-----|
| C1 | `GET /api/v1/current` — последнее измерение, `age_s` (никогда не отрицательный) и блок `aqi` по NowCast (`method: "nowcast_12h"`). Пустая БД → `{"ts": null}` | auto |
| H1 | `GET /api/v1/history?period=` принимает только `24h\|7d\|30d\|12m\|all`, иначе 400. Окна и корзины: 24ч/1ч, 7д/3ч, 30д/1сут, 364д/2сут, вся история/15сут | auto |
| H2 | `tz_offset` — минут к востоку от UTC, по умолчанию 0, допустимый диапазон ±840, иначе 400 | auto |
| H3 | Окна скользящие, а не календарные: `end` — начало корзины, в которую попал `now`; для `all` `start` — корзина первого измерения | auto |
| H4 | **Корзины привязаны к tz-сдвинутой сетке, а не к эпохе.** Регрессия не видна на `tz_offset=0`; тест-стражник `test_history_buckets_are_anchored_to_tz_shifted_grid_not_epoch` берёт `period=30d, tz_offset=330` — не упрощать его до UTC | auto |
| H5 | Сетка плотная: корзины без измерений отдаются с `null` и `n=0`, дыр в JSON нет | auto |
| H6 | Каждая точка несёт среднее по корзине, `<метрика>_lo`/`_hi` для всех пяти метрик (pm25, pm10, temperature, humidity, pressure), мгновенный `aqi` и `aqi_lo`/`aqi_hi`; `n` — число строк в корзине | auto |
| H7 | Ответ несёт `period`, `bucket_s`, `start`, `end`, `first_ts`, `points`; `first_ts` нужен фронту для скрытия вкладок периодов | auto |
| H8 | `GET /api/v1/hours?tz_offset=` — профиль суток: 24 часа местного времени, каждый усреднён по последним 7 суткам (окно кончается на границе текущего часа по tz-сдвинутой сетке). Час несёт `aqi` (по средним PM часа), `pm25`, `pm10`, `n`, `days`; конверт — `window_days`, `tz_offset`, `start`, `end`, `days_covered`. Сетка плотная (`null`, `n=0`), `tz_offset` валидируется как в H2. **Смысл ручки — устойчивость к простою**: сутки без данных не должны выедать в «худших часах» дыру | auto |
| Z1 | `GET /healthz` → `{ok, last_ts, rows}` | auto |
| D1 | `/` отдаёт дашборд, `/static` смонтирован, `/docs` — OpenAPI; CORS открыт на GET | both |
| D2 | `/api/v1/*` — та же база и для будущего Android-клиента: отдельного API-слоя под мобильный не заводим, ломающие правки контракта — осознанное решение, а не побочный эффект | manual |

## AQI (A)

| ID | Требование | Как |
|----|------------|-----|
| A1 | Breakpoints — US EPA, редакция 2024 (AirNow TAD, Table 6). **Не подгонять по памяти**: при правках сверяться с первоисточником. Самотест `python3 server/aqi.py` зелёный, эталоны: PM2.5 12.0→56, 35.4→100; PM10 155→101 | auto |
| A2 | Итоговый AQI = максимум sub-index'ов PM2.5/PM10, `dominant` — определяющий загрязнитель; категории `good\|moderate\|usg\|unhealthy\|very_unhealthy\|hazardous`; выше верхнего breakpoint — кап на 500 | auto |
| A3 | Концентрация обрезается до сетки breakpoints (PM2.5 → 0.1, PM10 → 1); регрессия float-обрезки: 55.4 → 150, не 151 | auto |
| A4 | `/current` — NowCast (12-часовое взвешенное среднее, вес в [0.5, 1]); `/history` — мгновенный AQI по средним корзины. Разные методы намеренно | auto |
| A5 | `server/aqi.py` — чистые функции без внешних зависимостей: переиспользуются будущим ботом и клиентом, FastAPI туда не затаскивать | manual |

## Веб-морда (U)

| ID | Требование | Как |
|----|------------|-----|
| U1 | Одна страница `server/static/index.html`, без сборки и внешних зависимостей: шрифты (Manrope, JetBrains Mono) вендорены в `server/static/fonts/` через `@font-face`, обращений к CDN нет | manual |
| U2 | Графики — свой SVG на клиенте; Chart.js не используется | manual |
| U3 | Шесть карточек метрик из `METRIC_DEFS` (AQI, PM2.5, PM10, температура, влажность, давление); клик по карточке переключает большой график, активная подсвечена; по умолчанию AQI | manual |
| U4 | Шаг оси Y и мин. размах — свои у каждой метрики (aqi 5/12, pm25 1/6, pm10 1/10, temperature 1/6, humidity 5/12, pressure 5/5); шкала строится от данных, а не от нуля; нижняя граница зажата нулём **только** у AQI | manual |
| U5 | Цвет: PM2.5/PM10/AQI — цвет текущей AQI-категории; температура/влажность/давление — фиксированные `METRIC_COLORS` (`#d97a4d`, `#4a90c4`, `#8b7dc4`), одинаковые в обеих темах | manual |
| U6 | Лента разброса: у AQI и пыли (PM2.5/PM10) на всех периодах **кроме `24h`**; у температуры/влажности/давления — никогда, хотя сервер и отдаёт им `_lo`/`_hi` | manual |
| U7 | Сетка Y: у AQI — пороги категорий (25/50/75/100/150/200/300) в цвет категории; у остальных метрик — четверти шкалы цветом `--line-strong` | manual |
| U8 | Тултип: время; величина, а рядом уровень словами у AQI и единица измерения у прочих; строка «диапазон lo–hi» — только там, где нарисована лента разброса; у AQI ещё строка «PM2.5 N · PM10 M». Всё содержимое сглажено тем же окном, что и линия, — тултип описывает одну точку кривой. Стоит в зарезервированной полосе **над** полем графика (`--tip-space`), поле не перекрывает; по горизонтали зажат по своей реальной ширине | manual |
| U9 | Вкладка периода видна, только если данных хватает на ≥30% её окна (`FILL_THRESHOLD`); `24h` видна всегда; `12m` и `all` делят порог | manual |
| U10 | AQI-герой: число, категория, шкала, вердикт человеческим языком и три рекомендации (окна / прогулка / спорт) по категории — на клиенте из `/current`. «Сводка за 24 часа» считается на клиенте из `/history?period=24h` (час максимума в заметке — из той же корзины, что и само число). «Худшие часы» — профиль суток из `/api/v1/hours` (H8), а не срез 24h: столбики подписаны «среднее за N дней» по `days_covered` | manual |
| U11 | Индикатор свежести: старше 300 с → «данные устарели» и красный стиль; возраст пересчитывается локально каждые 10 с | manual |
| U12 | Тёмная и светлая темы по `prefers-color-scheme`, обе рабочие; смена темы перерисовывает график и карточки | manual |
| U13 | Автообновление: `/current` раз в 60 с, `/history` раз в 300 с; ошибка сети не стирает уже показанные значения | manual |
| U14 | Пустые состояния осмысленны: «Пока нет данных» в герое, «нет данных за этот период» на графике, «Нет данных за 24 часа» в сводке, «Пока мало данных» вместо пустых столбиков в «худших часах» (подписи часов при этом скрыты) | manual |
| U15 | Источник правды по внешнему виду — макет в проекте Claude Design «Дизайн датчика качества воздуха», переносится руками. Осознанные отступления перечислены в [dashboard-metric-selector](dashboard-metric-selector.md); новые отступления — либо в макет, либо в вики | manual |

## Эксплуатация и поставка (O)

| ID | Требование | Как |
|----|------------|-----|
| O1 | Push в `main` → CI (`compileall` + pytest) → автодеплой на прод. Push в `dev` → тот же джоб `test`, затем деплой на бету. Красные тесты блокируют оба. На прод с `dev` не уезжает ничего: среда выводится из ref и падает в сторону беты | manual |
| O2 | `deploy/remote_setup.sh` идемпотентен; креды push прода в `/etc/tu4ka/env` генерируются один раз и при повторном прогоне не перегенерируются. Креды беты своими не бывают: на каждом бета-деплое `/etc/tu4ka-beta/env` переписывается копией прод-кредов, иначе бета отвечала бы 401 на зеркалированный пуш (O15) | manual |
| O3 | Пароль push на сервере обязан совпадать с прошитым в датчике — иначе датчик молча перестанет доставлять данные | manual |
| O4 | БД лежит вне корня среды (`/var/lib/tu4ka/tu4ka.db`, `/var/lib/tu4ka-beta/tu4ka.db`), чтобы `rsync --delete` при деплое её не задел | manual |
| O5 | Снаружи слушает nginx (80 и 443), приложение — только loopback: юнит `tu4ka` на `127.0.0.1:8000`, `tu4ka-beta` на `127.0.0.1:8001`; `/healthz` отвечает после деплоя | manual |
| O6 | Тесты — pytest в `tests/`, прогон `.venv/bin/python -m pytest -q`, все зелёные. Линтера в проекте нет — не заводить без просьбы | auto |
| O7 | Вики (`wiki/pages/`, `wiki/index.md`, `wiki/log.md`) обновляется вместе с изменением поведения — иначе она врёт | manual |
| O8 | Домен `amqi.am`: A-записи `amqi.am`/`www.amqi.am` (сайт), `push.amqi.am` (приём) и `beta.amqi.am` (бета) ведут на `178.160.230.131`, проксирование Cloudflare выключено на всех. Оранжевое облако ломает Let's Encrypt по HTTP-01 и не должно стоять на пути push. См. [domain-dns](domain-dns.md) | manual |
| O9 | Бета — поддомен `beta.amqi.am`, а не префикс пути: `index.html` ходит по корневым путям, и на префиксе бета молча читала бы API прода. Открыта без Basic auth, но отдаёт `X-Robots-Tag: noindex, nofollow`. См. [nginx-tls-beta](nginx-tls-beta.md) | manual |
| O10 | БД беты пересевается из прода на каждом бета-деплое через `VACUUM INTO` (не `cp` — база в WAL), строго прод→бета. Прод-база при этом открывается `mode=ro` | manual |
| O11 | `push.amqi.am` и голый IP остаются на HTTP:80 **без редиректа** на HTTPS: при кросс-схемном редиректе теряется `Authorization`, и прошивка может не пойти по 307 | manual |
| O12 | certbot работает только через `--webroot`; плагин `--nginx` не использовать — деплой перезаписывает конфиг, и правки плагина были бы затёрты. Выпуск загейчен наличием lineage, чтобы не упереться в rate limit LE | manual |
| O13 | Обновление не роняет запросы: слушающий сокет держит systemd (`tu4ka.socket`), на выкладке рестартуется только `.service`. Измерено 2026-08-04 на бета-деплое: 200 запросов из 200 — 200 OK, ноль отказов соединения, максимум ожидания 0.45 с (прод в тот же момент — 0.05 с) | manual |
| O14 | Версии зависимостей в `deploy/requirements.txt` запинены целиком, включая транзитивные: прод, бета и CI ставят одно и то же. Апгрейд — отдельным осознанным коммитом через бету | manual |
| O15 | Бета получает живые данные: nginx зеркалит `POST /api/v1/push` на `127.0.0.1:8001` (`mirror`, только пуш-путь, обе `:80`-локации). Ответ беты выбрасывается, таймауты до беты ≤ 2 с — ответ датчику не должен зависеть от беты. Зеркало живёт в прод-конфиге, так что включается прод-деплоем | manual |
| O16 | Ежедневный бэкап прода (`tu4ka-backup.timer`, 03:20 UTC, `Persistent=true`): `VACUUM INTO` из базы, открытой `mode=ro` → `PRAGMA integrity_check` **по файлу бэкапа** → `zstd`. Провал проверки роняет прогон и не запускает ротацию. Хранится 7 ежедневных + 6 ежемесячных; суммарный размер и остаток диска печатаются в журнал | manual |
| O17 | Офсайт-копия уходит в S3-совместимое хранилище штатным `curl --aws-sigv4` (без awscli/rclone). Ключи — в `/etc/tu4ka/env`, в git не попадают; скрипт из хранилища **ничего не удаляет** — срок жизни задаётся lifecycle-правилом провайдера. Провал загрузки не отменяет локальную копию, но даёт ненулевой код возврата | manual |
| O18 | Алерт о молчащем датчике (`tu4ka-alert.timer`, раз в 5 мин, порог 60 мин): сообщение в телеграм с cooldown 6 ч и **обязательным** сообщением о восстановлении ровно один раз. Неотправленное сообщение не считается доставленным — состояние не двигается. Токен бота не должен попадать в журнал: наружу отдаётся только тип ошибки | both |
| O19 | Внешний dead-man's switch (healthchecks.io) пингуется **только после** успешного `/healthz` с `"ok"` в теле и несколькими попытками. Безусловный пинг проверял бы живость таймера, а не приложения | manual |
| O20 | Бэкапы и алерты ставятся **только на прод**. У беты нет своих данных (пересев), а её алерт был бы ложной тревогой при живом проде, если сломается зеркало пуша. Восстановление проверяется руками раз в месяц по чек-листу в [backup-restore](backup-restore.md) — скачиванием **офсайт**-копии, не локальной | manual |

## Правовой пакет (L)

| ID | Требование | Как |
|----|------------|-----|
| L1 | Шесть страниц правового пакета (ToS, политика конфиденциальности, лицензия данных — ru и en) отдаются по стабильным URL `/legal/{terms,privacy,license}` и `/en/legal/{terms,privacy,license}`, 200 и `text/html`; неизвестный slug, неизвестный язык и попытки обхода пути → 404 | auto |
| L2 | Дисклеймер «ориентировочные измерения (indicative measurements)» стоит на видном месте страницы датчика — в AQI-герое, не в подвале — со ссылкой на лицензию данных | both |
| L3 | Измерения, агрегаты и публичные (смещённые) координаты распространяются под CC BY 4.0 со строкой атрибуции; страница лицензии ссылается на `creativecommons.org/licenses/by/4.0/` | auto |
| L4 | Условия использования содержат безотзывный неисключительный грант лицензии от владельца датчика на публикацию его данных | auto |
| L5 | Контракт удаления аккаунта закреплён в политике конфиденциальности: удаляются email/имя/точная координата/привязка «датчик → человек», измерения обезличиваются, датчик → `retired`. Реализация появится вместе с S6 (аккаунты) — проверка того, что код ей соответствует, тогда станет исполнимой | manual |
| L6 | Политика конфиденциальности называет оператора данных и контакт (`krotghar@gmail.com`), сроки ответа на запрос об удалении (5 дней) и исправлении (3 рабочих дня) по ст. 20 ХО-49-Н | auto |
