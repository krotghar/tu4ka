# Протокол приёма данных (airRohr push)

Датчик «тучка» — стандартная прошивка airRohr (NRZ-2024-135/RU, ID 2998975):
SDS011 (пыль) + BME280 (температура/влажность/давление). Раз в 60 с сам шлёт
`POST /api/v1/push` штатным механизмом прошивки «отправка на собственный API»
(HTTP basic auth). Формат менять нельзя — это конфигурация датчика, не наша.

## Тело запроса

```json
{
  "esp8266id": "2998975",
  "software_version": "NRZ-2024-135",
  "sensordatavalues": [
    {"value_type": "SDS_P1", "value": "9.82"},
    {"value_type": "SDS_P2", "value": "..."},
    ...
  ]
}
```

## Маппинг полей

| Поле прошивки          | Наше поле  | Примечание                     |
|-------------------------|------------|---------------------------------|
| `SDS_P1`                | `pm10`     |                                  |
| `SDS_P2`                | `pm25`     |                                  |
| `BME280_temperature`    | температура| BMP280_* тоже поддержан как альтернатива |
| `BME280_humidity`       | влажность  |                                  |
| `BME280_pressure`       | давление   | приходит в **Па**, храним в **гПа** |

`measurements.raw` хранит исходный JSON целиком — не только для отладки, это
страховка на случай будущих миграций схемы.

## Авторизация

Basic auth: user `tu4ka`, пароль — `TU4KA_PUSH_PASS` из `/etc/tu4ka/env` на
сервере. Должен совпадать с тем, что прошито в датчике (веб-конфиг датчика →
«Отправка данных на собственный API»). Путь `/api/v1/push`, порт 80 — тоже
зашиты в конфиге датчика, менять на сервере без переконфигурации датчика нельзя.
